# evidence/ —— 本组自己的证据材料

这个目录放**你们自己产出的、可以公开的证据**：培养方案截图、课程大纲、调试记录、实验日志、对照表。

放这里的唯一目的：让网站上的「来源」对**内部材料**也能点开。
外部文献（论文、官网）直接引原网址，不用放这里。

---

## 命名规范

```
2026-10-23-培养方案-AI2003M.pdf
2026-11-05-可视化调试-透明杯子-叠加图.png
2026-11-10-反例清单-第1周.md
```

`日期-类型-具体对象.扩展名`。日期用你拿到材料的那天，方便以后按时间排。

---

## 放进去之后怎么变成"可打开的链接"

仓库推到 GitHub 后，文件自动有两个地址，**任选一个**：

| 形式 | 地址 | 说明 |
| --- | --- | --- |
| 站点地址（推荐） | `https://3260105753-netizen.github.io/three-maps/evidence/文件名` | 和网站同域，直接在浏览器打开 |
| 仓库地址 | `https://github.com/3260105753-netizen/three-maps/blob/main/evidence/文件名` | 能看提交历史，适合需要"可追溯修改"的材料 |

把这个地址填进 `data/sources.json` 对应条目的 `url`，把 `verify` 改成 `已核实`，刷新页面就能点开了。

## 三条规矩

**① 只放需要的部分，不要整本**
培养方案放**相关的那一两页**就够。整本 PDF 既拖慢仓库，也放大了不必要的暴露面。

**② 去掉不该公开的东西**
学号、身份证号、手机号、家庭住址、成绩单上的个人排名——一律先裁掉或涂掉。

**③ 别人的东西不要放**
队友发你的材料要问过他；赛方提供的数据看比赛规则；网上下的文档不要转存，直接引原网址。

---

## 什么该放、什么不该放

| 放这里 ✅ | 不放这里 ❌ |
| --- | --- |
| 培养方案里证明某门课的那一页 | 整本培养方案 |
| 自己跑实验的截图、日志、报错原文 | 赛方的受限数据集 |
| 课程讲义里讲"三个观"的那一页 | 老师的完整课件 |
| 连续四周的反例清单 | 含同学真实姓名的聊天记录 |

---

## 为什么值得做

课程原文有一句：**"重要内容能够找到依据，区分事实、他人观点和团队推断。"**

外部文献证明"别人这么说过"；这个目录证明**"我们自己确实做过/查到过"**。
后者恰恰是「已经尝试」「待深入学习」这些理解程度最需要的支撑——没有它，"我们试过"只能算自述。
