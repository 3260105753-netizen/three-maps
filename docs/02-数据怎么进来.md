# 数据怎么进来

> 给三位地图负责人。**你不需要碰代码，也不需要碰 HTML。** 填表 → 跑一条命令 → 页面更新。

---

## 三条路，按需要选

| 方式 | 适合谁 | 优点 | 代价 |
| --- | --- | --- | --- |
| A. 填 CSV 再导入 | 一次交 5 条以上 | Excel 里看着舒服，校验报错指向行号 | 要先跑命令 |
| B. 直接改 JSON | 改一两条、加一个关系 | 最快，不用跑命令 | 少个逗号就整页白屏（有校验兜底） |
| C. 换演示数据集 | 想先看完整效果 | 一条命令换 66 个节点的成品 | 会覆盖 `data/`（自动备份） |

## A. CSV 流程（推荐）

### 1. 复制模板

```
templates/节点表.csv   → inbox/节点表.csv
templates/关系表.csv   → inbox/关系表.csv
templates/来源表.csv   → inbox/来源表.csv
```

Excel / WPS / Numbers 都能直接打开。模板带 BOM，中文不会乱码。

### 2. 节点表的列

```
id,map,name,type,summary,detail,understanding,understandingNote,evidence,verify,
sourceIds,tags,flags,owner,updated,courseLabel,courseAbility,courseBasis,
contribution,whyIncluded,results,caseStudy,revision
```

只填用得到的列，其余留空。几个要点：

- `map`：`domain` / `ecosystem` / `cognitive`，决定进哪张图
- `sourceIds`、`tags`、`flags`：多个值用分号分隔，如 `s.oxe;s.rt2`
- `caseStudy`、`revision`：这两列填**整段 JSON**。例如
  `{"problem":"…","method":"…","evidence":"…","judgment":"…","open":"…"}`
  只有「案例」「认识修正」节点才需要，其他节点留空
- `evidence` 只能是 `事实` / `他人观点` / `团队推断`
- `verify` 只能是 `已核实` / `待核实` / `来源待补`

### 3. 关系表

```
id,from,to,type,label,why,evidence,verify,inferred,sourceIds
```

- `inferred` 填 `是` 或 `否`
- `why` 写为什么成立，不是写「有关」
- 一条关系至少两个节点已经存在，否则会报「指向不存在的节点」

### 4. 来源表

```
id,title,url,publisher,date,kind,verify,note
```

没有链接就留空 `url` 并写 `verify=来源待补`。**不要编链接。**

### 5. 导入

```bash
node scripts/import-csv.mjs
```

输出长这样：

```
读取 节点表：6 行（inbox/节点表.csv）
读取 关系表：9 行（inbox/关系表.csv）

导入结果
  节点：新增 6 / 更新 0
  关系：新增 9 / 更新 0
  来源：新增 2 / 更新 0

⚠ 警告 3 条（不阻塞导入）
  · 节点 d.xxx：没写 understandingNote …

✓ 已写入 data/（导入前备份在 data/.backup/2026-10-17T11-20-33）
```

**有任何一条不合格，整批都不写入**，并列出具体行号：

```
✗ 有 2 个问题，本次没有写入任何文件
  ✗ 节点表第 4 行：type「其它」不在 domain 地图允许的类型里
  ✗ 关系表第 2 行：to 指向不存在的节点 d.not-exist
```

只想检查不想写入：加 `--dry`。

### 6. 刷新页面 + 补更新记录

导入成功后刷新浏览器即可看到。**然后必须在 `data/changelog.json` 加一条**：

```json
{
  "id": "ch-20261018-01",
  "date": "2026-10-18",
  "week": "第 5 周",
  "type": "内容",
  "who": "张三",
  "target": "领域地图：新增 6 个节点、9 条关系",
  "what": "补上从典型任务到技术路线的完整链路，新增两门课程节点",
  "why": "中期互评有 2 位同学说「不知道这些概念怎么串起来」",
  "basis": "反馈 fb-20261018-01 / 培养方案第 3 章",
  "links": ["domain.html"]
}
```

`type` 只能是：`技术` / `内容` / `反馈` / `修正` / `发布`。

## B. 直接改 JSON

打开 `data/domain.json`，照着已有节点复制一段改。注意：

- JSON 不能有注释、不能有尾逗号
- 中文引号（“”）不能当字符串分隔符，必须用英文 `"`
- 改完一定跑 `node scripts/validate.mjs`

改坏了也不要紧：`data/.backup/` 下有每次导入前的备份。

## C. 换数据集

```bash
node scripts/use-dataset.mjs --list        # 看有哪些
node scripts/use-dataset.mjs filled-example   # 换成完整的演示数据集（66 节点 / 62 关系）
```

会自动备份当前的 `data/`。想看「填满之后长什么样」，用这条命令最快。

## 分工与检查

| 谁 | 交什么 | 交给谁 |
| --- | --- | --- |
| 领域地图负责人 | 领域节点 + 课程节点 + 路线 | 技术同学导入 |
| 生态地图负责人 | 生态节点 + 它们与领域节点的连线 | 技术同学导入 |
| 认知地图负责人 | 观 / 分析方法 / 案例 / 习惯 / 认识修正 | 技术同学导入 |
| 证据负责人 | 来源表 + 标记失效链接 | 技术同学导入 |
| 技术同学 | 导入、校验、修页面、写更新记录 | — |

三条硬规则：

1. **关系必须有 `why`**，写「有关」等于没写。
2. **证据必须分类型**，推断要标 `inferred`。
3. **不确定就标出来**，`待核实` / `来源待补` 是诚实项，不是扣分项。
