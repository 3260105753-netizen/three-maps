## 一、选择：三条路，按你们的情况挑一条

| 方式 | 需要什么 | 适合 | 链接长什么样 |
| --- | --- | --- | --- |
| **GitHub Pages**（推荐） | GitHub 账号 | 想长期稳定、可以每周更新 | `https://<用户名>.github.io/<仓库名>/` |
| **Vercel** | Vercel 账号（可用 GitHub 登录） | 最快拿到链接 | `https://<项目名>.vercel.app` |
| **Netlify** | Netlify 账号 | 不想用 Git，直接拖文件夹 | `https://<项目名>.netlify.app` |

三者的配置文件都已经放在仓库里，不需要改任何代码。

## 二、GitHub Pages（推荐）

### 步骤

1. 新建仓库（Public），把整个 `three-maps-site` 目录的内容推到 `main` 分支。
2. 仓库 **Settings → Pages → Build and deployment → Source** 选 **GitHub Actions**。
3. 推一次代码，`.github/workflows/pages.yml` 会自动跑：
   - 先执行 `node scripts/validate.mjs`（数据不合格直接失败，避免把坏数据发上线）
   - 再发布到 Pages
4. 等 Actions 变绿，在 Pages 页面能看到网址。

### 命令

```bash
git init
git add .
git commit -m "init: 三张活地图 V0"
git branch -M main
git remote add origin https://github.com/<用户名>/<仓库名>.git
git push -u origin main
```

### 常见坑

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 页面 404 | 仓库是 Private，或 Pages 没开 | 改 Public，Settings → Pages 选 GitHub Actions |
| 页面没样式 | 打开的是 `/仓库名` 没带斜杠 | 用 Pages 给出的完整网址 |
| 只有 README 显示 | 没选 GitHub Actions，走了默认 Jekyll | 改 Source 为 GitHub Actions（仓库里已有 `.nojekyll`） |
| 改了数据但页面没变 | CDN 缓存 | 强制刷新；`data/` 已设 no-cache，但仍可能有几分钟延迟 |

## 三·补：本项目实际使用的地址

- 线上站点：<https://3260105753-netizen.github.io/three-maps/>
- 仓库：<https://github.com/3260105753-netizen/three-maps>


## 五、发布后必须做的访问测试

课程要求「提交前，请非本组同学使用自己的设备和网络实际打开网站」。所以每次发布至少测这几项：

### 测试清单（照着做，10 分钟）

| # | 测什么 | 怎么算通过 |
| --- | --- | --- |
| 1 | 首页能否打开 | 三张地图入口卡片都出现，统计数字不是 0 |
| 2 | 手机能否打开 | 用流量、不用 Wi-Fi，能滚动、能点节点 |
| 3 | 节点卡是否完整 | 名称 / 类型 / 说明 / 理解程度 / 关系 / 来源 六项都在 |
| 4 | 关系能否跳转 | 点关系里的另一个节点，能跳到对应地图并高亮 |
| 5 | 来源能否打开 | 点一个来源链接，能打开真实页面（不是 404） |
| 6 | AI 能力 1 | 输入一个概念，返回节点 + 课程 + 学习基础 + 引用块 |
| 7 | AI 能力 2 | 选两个节点，出现路径或明确说「没有连通路径」 |
| 8 | AI 能力 3 | 选两条路线，出现共有 / 独有 / 风险提示 |
| 9 | 更新记录 | 至少有一条记录，且五项（日期 / 对象 / 内容 / 依据 / 原因）齐全 |
| 10 | 自检清单 | `about.html#checks` 13 项都能勾选，刷新后进度还在 |
| 11 | 无密钥要求 | 全程没有要求输入任何账号或 API Key |
| 12 | 控制台无报错 | F12 → Console 没有红色错误 |

### 发现并修掉的问题（如实记录）

| # | 问题 | 原因 | 修法 |
| --- | --- | --- | --- |
| 1 | 首页整页显示「数据没有加载出来」 | `hero()` 里误用了外层不存在的 `state` 变量 | 改为把 `demoContent` 作为参数传入 |
| 2 | 地图页白屏，报 `reading 'd.sample-concept'` | 渲染关系时读 `state.adj`，实际数据在 `state.index.adj` | 统一改走 `engine.neighbors()` |
| 3 | 关系图不显示 | 重构时漏了 `drawGraph()` 的调用 | 补上调用 |
| 4 | 浏览路径永远显示「没有足够关系」 | 同上，`adj` 条目里没有 `node` 字段 | 改用 `neighbors()` 返回的 `{node, rel}` |
| 5 | 关于页显示「页面脚本缺失」 | `about.js` 有一处引号不匹配导致整个文件语法错误 | 修正引号，并加了 `node --check` 全量语法检查 |
| 6 | 节点少时关系图松散、标签被截断 | 4 个节点用力导向布局效果差 | ≤6 个节点改用圆环布局；标签截断从 10 字放宽到 14 字并加 tooltip |

## 七、每周维护动作（10 分钟）

1. `node scripts/validate.mjs` —— 有没有新增的坏数据
2. 打开三个来源链接抽查 —— 有没有 404（失效就改 `sources.json` 里的 `verify`）
3. 看 `data/feedback.json` —— 有没有未处理的反馈
4. 写一条 changelog —— 就算「本周检查了，无新增内容」也写
5. 发布一次 —— 让线上始终是最新版本
