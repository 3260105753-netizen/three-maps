# AI 能力计划（一页）

> 课程要求：**至少实现一项与地图直接相关的 AI 能力**，且「涉及事实的回答应能够回到地图内容或可靠来源，没有依据时应说明不确定，不能编造课程、论文或人物关系」。
> 这一页说明我们怎么满足它，以及为什么这么实现。

---

## 一、做了什么

三项能力，都直接读三张地图的节点与关系。

| # | 能力 | 用户问什么 | 系统用什么地图数据回答 | 输出里的强制项 |
| --- | --- | --- | --- | --- |
| 1 | **概念查课程** | 「我想学这个概念，先学什么？有什么课？用什么工具？」 | 目标节点 + 指向它的 `前置` 关系（课程节点）+ `依赖/包含/采用` 关系（工具与基础） | 命中节点、课程表（含标签与依据）、学习基础、工具、来源、理解程度 |
| 2 | **关系解释** | 「这两个节点到底怎么联系起来的？」 | 关系图上的最短路径（最多 6 跳），每跳取 `type / label / why / evidence / verify / sourceIds` | 路径链、逐跳理由、证据类型、核实状态、引用节点与来源 |
| 3 | **路线比较** | 「这两条技术路线有什么区别？各自依赖什么？」 | `routes.json` 两条路线的节点集合做交集/差集，再按 `type` 分组，附生态节点 | 共有依赖、各自独有依赖、生态对照、风险（待深入学习 / 无来源节点） |

对应页面：`ai.html`。

---

## 二、每个回答都带三样东西

不管问哪一项，回答区最后固定出现「这条回答的引用」三栏：

1. **引用了哪些地图节点** —— 可点击，跳回节点卡
2. **来源链接** —— 可打开；没有可打开来源的会单列成「来源待补」
3. **团队理解程度** —— 已初步理解 / 已经尝试 / 待深入学习各几个，并列出最薄弱的节点

这是硬性渲染逻辑，不是「尽量带上」：所有能力都调用同一个 `citations()` 函数生成这段，任何一项没有引用都不给结论。

---

## 三、为什么不用「通用聊天机器人」

| 通用聊天 | 本方案 |
| --- | --- |
| 答案来自模型参数，无法核对 | 答案只能来自 `data/`，每条都能点回节点 |
| 很可能编造课程名、论文、机构关系 | 地图里没有就明说没有，并提示「先补节点」 |
| 现场演示依赖网络与额度 | 纯前端计算，断网也能演示 |
| 会向使用者索取 API Key | 全站不调用任何外部 API，不需要密钥 |
| 每次回答可能不同 | 同样的输入必然得到同样的输出，可复现 |

课程原文那句「AI 回答不能作为事实证据」，我们理解为：**AI 的职责是把地图里的东西找出来、串起来、标清楚证据等级，而不是替地图生产新事实。**

---

## 四、不确定时怎么表现（三条具体行为）

1. **检索不到** → 直接说「地图里没有找到 X」，列出当前已有标签，并提示应该先把它作为节点补进地图。不会换个说法编一个。
2. **两个节点不连通** → 明说「6 跳以内没有路径」，给出三种可能原因（跨图关系没建 / 确实无关 / 节点刚加入），不替你造一条中间路径。
3. **路径上有推断** → 在这一跳上打「推断，未证实」标签，并在结论区统计「N 条关系中 M 条是推断」。

这三条都能在 `ai.html` 上手动触发验证。

---

## 五、边界（明写出来，避免被当成缺陷）

- 地图里没有的节点查不出来 —— 这是设计，不是 bug
- 不判断内容对不对，只忠实呈现你们登记的判断与来源
- 不跟踪论文更新，只反映上次导入的数据
- 不做多轮对话：每次提问独立，不记忆上下文（课程没要求，且会引入不确定性）
- 关系图超过 60 个节点会开始拥挤，需要拆分地图或加筛选

## 六、后续可扩展（有余力再做，非必需）

| 方向 | 做法 | 风险 |
| --- | --- | --- |
| 相似节点推荐 | 用 tags + 共现关系算相似度 | 低 |
| 失效链接检查 | 脚本定期 HEAD 请求所有 `url`，把失败的标 `verify=待核实` | 低，适合证据负责人 |
| 论文更新提示 | 抓 arXiv 关键词，人工筛后进「待核实线索」区 | 中，必须人工复核 |
| 自然语言问答 | 在检索到的节点子集上接一个大模型，**只允许基于给定上下文回答**，并强制输出引用的节点 id | 高，需要密钥与网络，现场演示有翻车风险 |

最后一项如果真的做，必须保留现在的确定性引擎作为兜底：现场演示默认走引擎，大模型是可选增强。

---

## 七、验收对照

| 课程要求 | 本方案对应 |
| --- | --- |
| 至少一项与地图直接相关的 AI 能力 | 三项，均读地图数据 |
| 回答能回到地图内容或可靠来源 | 强制引用块，节点可点击、来源可打开 |
| 没有依据时说明不确定 | 三种「不知道」的明示行为 |
| 不能编造课程、论文、人物关系 | 不生成文本，只检索与遍历已有数据 |
| 中期可有初步演示 | 现在即可演示，不需要额外配置 |

---

## 八、演示时的三句话脚本

1. 「我先输入一个概念。」→ 展示命中节点 + 相关课程 + 学习基础。
2. 「我再问两个看起来不相关的节点。」→ 展示逐跳路径 + 每一跳的理由与来源。
3. 「最后问一个它答不上来的。」→ 展示「地图里没有」——这是最能说明「不是通用聊天」的一幕。
