# 节点字段契约

> 给三位地图负责人、证据负责人看的一页。
> 一句话：**不接受「给我一段文字」，只接受这几种字段。** 缺字段会被脚本拦下，交不进去。

---

## 为什么必须固定字段

三张地图如果各写各的，会出现三种事故：

1. **对不上**：领域地图叫「检索增强」，生态地图叫「RAG」，认知地图叫「检索增强生成」——三个节点，三条关系，谁也连不上谁。
2. **连不起来**：只有名字没有关系，图上全是孤岛，点进去只有一句话，没有「为什么」。
3. **查不到依据**：写「有研究表明」，但打不开、指不到具体段落，互评时一问就穿。

固定字段解决的是这三件事，不是形式主义。

---

## 一、节点（node）

每个节点是一张卡。页面上的卡片就是按这张表渲染的。

| 字段 | 必填 | 说明 | 反例 → 正例 |
| --- | --- | --- | --- |
| `id` | ✅ | 全局唯一。前缀 `d.` 领域 / `e.` 生态 / `c.` 认知，后面用英文小写与短横线 | `节点1` → `d.pick-place` |
| `name` | ✅ | 显示名，中文为主，6–14 字最好 | `关于那个东西` → `桌面抓取与放置` |
| `type` | ✅ | 必须在该地图允许的类型里（见下表） | `其他` → `技术路线` |
| `summary` | ✅ | **一句话说明**：它是什么、解决什么问题。不少于 8 字，能独立读懂 | `很重要` → `机器人看着桌面，把指定物体抓起来放进盒子` |
| `understanding` | ✅ | 只能三选一：`已初步理解` / `已经尝试` / `待深入学习` | `懂了` → `已经尝试` |
| `understandingNote` | ⚠️ | 为什么是这个程度。不写就会被追问「凭什么说已经理解」 | `—` → `跑通过仿真里的单物体抓取，真机没上手` |
| `evidence` | ✅ | 证据类型：`事实` / `他人观点` / `团队推断` | `资料` → `他人观点` |
| `verify` | ✅ | 核实状态：`已核实` / `待核实` / `来源待补` | `不确定` → `待核实` |
| `sourceIds` | ✅ | 来源编号数组，必须先在 `sources.json` 里登记 | `["论文"]` → `["s.oxe","s.rt2"]` |
| `owner` | ✅ | 谁对这个节点负责 | `我们组` → `张三` |
| `updated` | ✅ | 最后修改日期 `YYYY-MM-DD` | `上周` → `2026-10-17` |
| `detail` | ⚠️ | 2–3 句展开，解释「为什么值得单独拿出来讲」 | 可选 |
| `tags` | ⚠️ | 检索用标签，2–4 个 | `["操作","评测"]` |
| `flags` | ⚠️ | 页面上的黄色告警标签，如「来源待补」「待核实」 | `["来源待补"]` |

### 按类型额外必填

| 当 `type` 是 | 还必须写 | 为什么 |
| --- | --- | --- |
| `课程` | `courseLabel`（前置基础 / 核心覆盖 / 部分涉及 / 实践应用 / 自主拓展）、`courseAbility`、`courseBasis` | 课程关联必须有培养方案或大纲依据，不能凭课名猜 |
| `会议` `实验室` `企业` `开源社区` `数据集` `基准` `信息渠道` | `contribution`（主要贡献）、`whyIncluded`（入选理由）、`results`（相关成果） | 生态地图不能只是名单 |
| `案例` | `caseStudy`：`problem` → `method` → `evidence` → `judgment` → `open` | 让同学看到分析过程，不是只看结论 |
| `认识修正` | `revision`：`before` → `trigger` → `now` → `unknown` | 这是「中期以来有实际变化」的唯一证据 |

### 每张地图允许的类型

- **领域地图**：典型任务 / 问题 / 概念 / 方法 / 技术路线 / 模型 / 软件 / 数据与资源 / 课程
- **生态地图**：会议 / 实验室 / 企业 / 开源社区 / 数据集 / 基准 / 信息渠道
- **认知地图**：认识方法（观）/ 分析方法 / 习惯 / 案例 / 认识修正

## 二、关系（relation）

**关系是这张地图真正的价值所在。** 只有节点没有关系，做出来的是一份清单。

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `id` | ✅ | 如 `r12`，全局唯一 |
| `from` | ✅ | 起点节点 id |
| `to` | ✅ | 终点节点 id。方向必须是有意的：`from` 指向 `to` |
| `type` | ✅ | 见下方关系类型表 |
| `label` | ⚠️ | 箭头上的短语，让方向读起来通顺，如「需要先解决」「是它的前置课程」 |
| `why` | ✅ | **为什么这条连线成立。** 不少于 8 字。写「有关」等于没写 |
| `evidence` | ✅ | `事实` / `他人观点` / `团队推断` |
| `verify` | ✅ | `已核实` / `待核实` / `来源待补` |
| `inferred` | ⚠️ | 布尔值。未经证实的联系必须 `true` 且 `evidence` 写「团队推断」，页面上会显示「推断」 |
| `sourceIds` | ⚠️ | 这条关系的依据，可以和节点的来源不同 |

### 关系类型（只能用这些）

| 类型 | 读法 |
| --- | --- |
| `依赖` | A 成立需要 B |
| `前置` | A 是学 B 之前要先有的基础（课程挂概念就用它） |
| `替代` | A 可以取代 B，或正被 B 取代 |
| `对比` | A 与 B 常被放在一起比较 |
| `协同` | A 与 B 组合使用效果更好 |
| `用于` | A 被用来解决 B |
| `包含` | A 包含 B 作为组成部分 |
| `暴露` | A 让 B 这个问题显现出来 |
| `质疑` | A 对 B 的结论构成挑战 |
| `体现` | A 是 B 的一个具体实例 |
| `采用` | A 使用了 B 的方法或成果 |
| `提供` | A 向 B 输出数据、代码或能力 |
| `合作` | A 与 B 有共同产出 |
| `竞争` | A 与 B 在同一生态位争夺资源 |
| `资助` | A 为 B 提供资金或算力 |
| `对应` | 生态里的 A 就是领域里的 B（同一对象两个视角） |

> 跨图连线是允许的，也是必须的。领域节点和生态节点之间用 `对应` / `提供` / `采用`；认知地图的案例用 `体现` / `质疑` 指回领域节点。

## 三、来源（source）

在 `sources.json` 里登记一次，节点与关系只引用编号。这样链接失效时改一处，全站生效。

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `id` | ✅ | `s.xxx` |
| `title` | ✅ | 标题原文，不要自己概括 |
| `url` | ⚠️ | 可打开的链接。**没有就留空并标「来源待补」，不要编一个** |
| `publisher` | ⚠️ | 出版方 / 网站 |
| `date` | ⚠️ | `YYYY-MM` |
| `kind` | ✅ | 论文 / 官方文档 / 官方页面 / 代码仓库 / 会议官网 / 目录 / 信息渠道 / 待补 |
| `verify` | ✅ | `已核实` / `待核实` / `来源待补` |
| `note` | ⚠️ | 这个来源具体支撑了什么判断 |

---

## 四、理解程度：只能用这三档

| 取值 | 含义 | 用它的时机 |
| --- | --- | --- |
| `已初步理解` | 能够解释基本作用和主要关系 | 能用自己的话讲清楚，能举一个例子 |
| `已经尝试` | 完成过一个实际任务或简单示例 | 亲手跑过、写过、测过 |
| `待深入学习` | 知道其位置和价值，但尚未掌握细节 | 只读过介绍，没有动手 |

**不要**把「听说过」写成「已经掌握」。这一栏是给互评同学看的诚实地图，写得高反而更危险。

## 五、证据：必须分三类

| 取值 | 含义 |
| --- | --- |
| `事实` | 有可核对的一手依据（论文原文、官方文档、自己跑出的结果） |
| `他人观点` | 别人的判断或主张，你转述但未亲自验证 |
| `团队推断` | 我们自己的推理与判断，尚无直接证据 |

`团队推断` 的内容在页面上会显示为推断，并且**不能**同时标 `已核实`。

## 六、交之前跑一遍

```bash
node scripts/validate.mjs
```

会拦下这些：

- 缺必填字段
- `type` 不在该地图允许的类型里
- `understanding` / `evidence` / `verify` 写了自己的说法
- `sourceIds` 指向没登记的来源
- 关系指向不存在的节点
- 课程节点没有依据
- 案例缺五段中的某一段
- 标了 `inferred` 但 `evidence` 不是「团队推断」

报错会指出**文件名 + 第几个节点**，改完再跑一次即可。

---

## 七、最常见的三类错误

1. **一句话塞进 summary**：写了 200 字。→ summary 一句话，展开写进 `detail`。
2. **关系写成「有关系」**：`why: "两者有关联"`。→ 必须写清「A 需要 B 提供什么」。
3. **课程没有依据**：写了课名就完事。→ 必须补 `courseBasis`，指到培养方案或大纲的哪一段；没拿到原文就标 `待核实` 并写进 `flags`。
