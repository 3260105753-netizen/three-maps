# 填表须知（给三位地图负责人）

网站已经上线，你只需要填表，不用碰代码、不用装任何东西。

**怎么交**：填好下面两个 CSV，发给技术同学（微信直接发文件即可），剩下的我来导。

---

## 一、节点表（`节点表.csv`）

一行一个节点。**标 ★ 的必须填**。

| 列 | 说明 |
| --- | --- |
| ★ `id` | 唯一编号。领域 `d.xxx`、生态 `e.xxx`、认知 `c.xxx`，小写英文+短横线，如 `d.grasp` |
| ★ `map` | `domain` / `ecosystem` / `cognitive` 三选一 |
| ★ `name` | 显示名，6–14 字最好 |
| ★ `type` | 见下面第二节，不能自己编 |
| ★ `summary` | **一句话**说清它是什么、解决什么问题。不少于 10 字，要能独立读懂 |
| `detail` | 可选，2–3 句展开 |
| ★ `understanding` | 三选一：`已初步理解` / `已经尝试` / `待深入学习` |
| `understandingNote` | 为什么是这个程度（不写会被追问） |
| ★ `evidence` | 三选一：`事实` / `他人观点` / `团队推断` |
| ★ `verify` | 三选一：`已核实` / `待核实` / `来源待补` |
| `sourceIds` | 来源编号，多个用分号：`s.oxe;s.rt2`（先看来源表） |
| `tags` | 分号分隔，2–4 个 |
| `owner` | 你的名字 |
| ★ `updated` | `2026-10-17` 这种格式 |

### 按类型还要加填的列

| 如果 `type` 是 | 还要填 |
| --- | --- |
| `课程` | `courseLabel`（前置基础/核心覆盖/部分涉及/实践应用/自主拓展）、`courseAbility`、`courseBasis`（依据哪份培养方案，没有就写"待补"） |
| `会议` `企业` `开源社区` `实验室` `数据集` `基准` `信息渠道` | `contribution`（主要贡献）、`whyIncluded`（入选理由）、`results`（相关成果） |
| `案例` | `caseStudy` 列，填整段 JSON：`{"problem":"…","method":"…","evidence":"…","judgment":"…","open":"…"}` |

## 二、允许的类型（不能自己发明）

- **领域地图**：典型任务 / 问题 / 概念 / 方法 / 技术路线 / 模型 / 软件 / 数据与资源 / 课程
- **生态地图**：会议 / 实验室 / 企业 / 开源社区 / 数据集 / 基准 / 信息渠道
- **认知地图**：认识方法（观）/ 分析方法 / 习惯 / 案例 / 认识修正

---

## 三、关系表（`关系表.csv`）

**关系比节点重要。** 只有节点没有关系，做出来是一份清单。

| 列 | 说明 |
| --- | --- |
| ★ `id` | `r100`、`r101` 这样编号 |
| ★ `from` / `to` | 起点节点 id 和终点 id，方向要有意义 |
| ★ `type` | 见下表，只能用这些 |
| `label` | 箭头上的短语，如"需要先解决""是它的前置课程" |
| ★ `why` | **为什么这条连线成立**，不少于 10 字。写"有关"等于没写 |
| ★ `evidence` | `事实` / `他人观点` / `团队推断` |
| ★ `verify` | `已核实` / `待核实` / `来源待补` |
| `inferred` | 是推断就填 `是`，且 `evidence` 必须写"团队推断" |
| `sourceIds` | 这条关系的依据，可以和节点的不同 |

关系类型：依赖 / 前置 / 替代 / 对比 / 协同 / 用于 / 包含 / 暴露 / 质疑 / 体现 / 采用 / 提供 / 合作 / 竞争 / 资助 / 对应

> 跨图连线也填在这张表里：生态节点对应领域节点用 `对应`，认知案例指回领域节点用 `体现` 或 `质疑`。

---

## 四、来源表（`来源表.csv`）

| 列 | 说明 |
| --- | --- |
| ★ `id` | `s.xxx` |
| ★ `title` | 标题原文，不要自己概括 |
| `url` | 能打开的链接。**没有就留空，并把 verify 写"来源待补"，不要编** |
| `publisher` | 出版方 |
| `date` | `2023-10` 这种格式 |
| ★ `kind` | 论文 / 官方文档 / 官方页面 / 代码仓库 / 会议官网 / 目录 / 信息渠道 / 待补 |
| ★ `verify` | `已核实` / `待核实` / `来源待补` |
| `note` | 这个来源具体支撑了什么判断 |

---

## 五、三条硬规则（违反会被打回）

1. **关系必须写 `why`** —— 不是"两者有关"，是"A 需要 B 提供什么"。
2. **证据要分类型** —— 事实 / 他人观点 / 团队推断。推断要在关系上标 `inferred=是`。
3. **不确定就标出来** —— 没链接就写"来源待补"、没查到就写"待核实"。这些在页面上会显示成黄色告警，**不扣分，是诚实项**；编造才扣分。

---

## 六、数量要求（中期够用就行）

| 谁 | 最少交 |
| --- | --- |
| 领域负责人 | 5 个节点 + 6 条关系，每个节点至少 1 条能打开的来源 |
| 生态负责人 | 5 个节点 + 4 条关系（含和领域节点的对应关系） |
| 认知负责人 | 1 个「观」+ 1 个案例（五段式）+ 1 条认识修正 |

先把量凑够让页面不空，后面再补细节。**别等"想全了"再交。**
